> 本文件先釐清「哪些內容是使用者的產品要求」以及「哪些內容只是附件提供的作業／版型約束」。本階段只產出規劃文件，不建立應用程式功能。

## 2. 已確認的產品意圖

1. 產品是可放在 GitHub Pages 的語音轉錄器，預設應優先考慮瀏覽器本地處理。
2. 使用者可輸入自己的 OpenAI、Grok（xAI）、Google 或 CGU API Key。
3. Key 必須先測試，再讀取可用模型，最後由使用者選擇模型。
4. 所選模型用於語句修飾／會議文件整理，而不是把 API Key 交給專案擁有者。
5. 使用者可加入 PDF 與文字資料，作為專有名詞、姓名及語句修飾的參考。
6. 會議輸出須遵守附件 `AGENTS.md` 的三步驟：會後通知信、完整會議紀錄／決策脈絡、待辦追蹤／下次議程。
7. 另須輸出可離線開啟、A4 直式列印／另存 PDF 的整合 HTML，遵循附件版型的 CSS 與安全要求。

## 3. 附件規則轉成產品要求

### 3.1 來自 `AGENTS.md` 的內容規則

- 來源不明的姓名、日期、期限、投票結果、決策理由不得由 AI 自行補寫。
- 明確決議、明確指派、待確認／暫定、一般建議要分開標記。
- 決策使用穩定 ID：`DEC-YYYYMMDD-01`；日期未知時使用 `DEC-DATE-UNKNOWN-01`。
- 待辦使用穩定 ID：`ACT-YYYYMMDD-01`，必須有主責、完成標準、期限、狀態、關聯決策與來源。
- 未決、受阻、逾期、缺主責／期限或待驗收事項要進入下次會議議程。
- 通知信是草稿，產品不得自動寄信、通知第三人或建立行事曆。
- 同一份結構化資料必須渲染出四份 Markdown 與一份 A4 HTML，避免內容不一致。

### 3.2 來自 A4 HTML 範本的版面規則

- `@page { size: A4 portrait; margin: 16mm 15mm 16mm 15mm; }`。
- 單一 HTML 可離線開啟；CSS 內嵌，不依賴 CDN、外部字型、外部圖片或網路連線。
- 繁體中文系統字型優先；正文約 10–11pt、行距 1.45–1.6。
- 長文字、姓名、網址、程式碼可換行；過寬的十欄待辦表改用任務卡片或精簡表格＋詳情。
- 列印時隱藏按鈕；可提供 `window.print()`，但不取代瀏覽器列印。
- 來源文字必須 HTML escape，不可把逐字稿中的 HTML／script 當成可信標記。

## 4. 參考 Whisper Web 的觀察

截至 2026-10-25，指定 Space 的公開設定顯示為 `sdk: static`，並列出多個 Xenova Whisper／Distil-Whisper 模型；頁面描述支援上傳音訊或直接錄音並轉為文字。這支持本產品採用「靜態前端＋瀏覽器端推論」的方向，但不代表本專案必須複製該 Space 的程式碼或 UI。

本產品應另外處理：繁體中文品質、說話者／時間碼編輯、專有名詞保護、PDF／文字參考、四份會議文件與 A4 HTML，以及多家 LLM provider 的 Key／模型流程。

## 5. 規劃階段仍需確認的事項

- CGU `api_call.html` 背後實際請求 URL、HTTP method、認證欄位、模型清單格式、生成格式及 CORS 是否允許 GitHub Pages 來源。
- 是否要支援雲端語音辨識；MVP 先以瀏覽器本地 Whisper 為基線。
- 是否需要說話者分離（speaker diarization）；Whisper 本身不等於可靠的說話者辨識。
- 允許的單檔音訊／PDF 大小與瀏覽器最低版本。
- API Key 是否只允許記憶體暫存，或由使用者明確選擇後暫存於本機；預設不持久化。
- 最終產品名稱、GitHub repository 名稱、授權條款與隱私聲明內容。

## 6. 本次文件的適用範圍

本次工作不是整理某一場實際會議，因此不建立 `meetings/YYYY-MM-DD_會議名稱/`、`tracking/` 或四份會議成果檔；附件中的會議輸出規則只被轉譯為未來產品的生成規格。等產品實作完成並處理真實逐字稿時，才依 `AGENTS.md` 產生那些會議檔案。
