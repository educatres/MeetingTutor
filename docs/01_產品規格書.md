# MeetingTutor 語音轉錄與會議紀錄整理器｜產品規格書

版本：0.1（規劃稿）  
狀態：MVP 已實作，供後續驗收與擴充討論  
目標部署：GitHub Pages（靜態網站）

## 1. 產品定位

MeetingTutor 將錄音或音訊檔轉成可編輯的逐字稿，再由使用者指定的 LLM 進行「保留事實的語句修飾」與會議文件整理。使用者可以提供專有名詞／姓名參考資料，讓模型在修飾時優先採用正確寫法，同時保留原文、修訂內容與不確定性。

核心原則：

- 音訊預設在瀏覽器本地處理，避免會議錄音先上傳到本專案伺服器。
- LLM API Key 由使用者自行提供、只在其瀏覽器工作階段使用，專案不代管 Key。
- AI 可修飾表達，不可把猜測變成已確認的會議事實。
- 原始逐字稿永遠可回看、可下載，任何 AI 修訂都可比較與復原。

## 2. 使用者與使用情境

| 角色 | 主要目的 |
|---|---|
| 會議主持／紀錄者 | 快速得到可寄出的會後通知、決策脈絡與待辦 |
| 研究／專案人員 | 用自有詞彙表、前次紀錄或 PDF 讓專有名詞更準確 |
| 重視隱私的使用者 | 不把音訊交給第三方服務，僅在必要時呼叫自選 LLM |

典型流程：匯入／錄音 → 瀏覽器轉錄 → 修正逐字稿與說話者 → 上傳參考資料 → 輸入並測試 API Key → 選模型 → 產生草稿 → 檢閱差異／待確認 → 匯出 Markdown 與 A4 HTML。

## 3. MVP 範圍

### 3.1 必做功能

| ID | 功能 | 驗收重點 |
|---|---|---|
| FR-001 | 匯入音訊檔 | 支援常見瀏覽器可解碼格式；顯示檔名、長度、大小與錯誤原因 |
| FR-002 | 麥克風錄音 | 可開始／暫停／停止；停止後可直接轉錄；顯示麥克風權限狀態 |
| FR-003 | 瀏覽器端 Whisper 轉錄 | 以 Web Worker 執行，UI 不凍結；顯示模型下載／轉錄進度；轉寫語言預設中文，並可切換英文 |
| FR-004 | 逐字稿編輯 | 編輯段落、時間碼、說話者、原文；保留原始版本與修改歷史 |
| FR-005 | API Key 管理 | Provider、Key、可選 base URL／專案欄位；Key 顯示遮罩；預設只存記憶體 |
| FR-006 | 測試 Key | 按下「測試」後發出最小請求；清楚顯示成功、認證失敗、配額、CORS、網路錯誤 |
| FR-007 | 讀取模型清單 | 測試成功後取得 provider 可用模型；模型需顯示名稱、能力（文字生成等）與來源 |
| FR-008 | 模型選擇 | 使用者選定 provider／model；重新整理後不應默默沿用失效設定 |
| FR-009 | 參考資料 | 匯入 PDF、TXT、MD（MVP）；顯示檔名、頁數／字數、解析錯誤；可刪除 |
| FR-010 | 詞彙表／姓名保護 | 可手動新增正確寫法、別名、禁止替換、備註；從參考資料擷取的詞彙須可確認後採用 |
| FR-011 | AI 語句修飾 | 以原文為主，輸出修訂稿、變更摘要、專有名詞警示與來源依據 |
| FR-012 | 會議成果生成 | 產生會後通知信、完整會議紀錄、待辦追蹤、下次議程，遵循 `AGENTS.md` |
| FR-013 | A4 HTML | 產生獨立、可離線開啟、A4 直式列印／另存 PDF 的整合 HTML |
| FR-014 | 匯出 | 可下載 TXT／Markdown／JSON／HTML；不得聲稱已寄信或已建立行事曆 |
| FR-015 | 重新整理與復原 | AI 結果可接受、拒絕、重試；保留原始逐字稿 |

### 3.2 明確不納入 MVP

- 專案伺服器、使用者帳號、雲端同步與團隊協作。
- 由本產品代替使用者保管或轉發 API Key。
- 自動寄 Email、發 LINE／Teams／Slack 或建立行事曆。
- 可靠的多語者聲紋辨識、即時多人會議串流、錄音雲端備份。
- 未經確認的 CGU 非公開 API 或繞過 CORS 的代理服務。

## 4. Provider 規格

### 4.1 統一體驗

1. 使用者選 provider。
2. 輸入 Key（必要時輸入自訂 endpoint／project／location）。
3. 顯示資料用途與「Key 不會上傳至 MeetingTutor」的提示。
4. 按「測試並取得模型」；先完成認證測試，再顯示模型清單。
5. 使用者選模型；可用「發送短測試提示」確認生成能力，但預設不送會議內容。

### 4.2 Provider 需求表

| Provider | 模型清單／測試方向 | 主要風險或待確認 |
|---|---|---|
| OpenAI | 以使用者提供的相容 API base URL 呼叫 models；文字生成採相容的 Responses／Chat Completions adapter | 瀏覽器 CORS、不同帳戶可用模型不同；不得硬編碼模型名 |
| xAI／Grok | 以 xAI 公開 API 的 models 與 OpenAI 相容生成格式為基線 | endpoint、CORS、可用模型與 API 版本需以官方文件驗證 |
| Google | 讀取 Gemini models，將模型能力映射到統一文字生成介面 | Google API Key 傳遞方式、模型欄位及瀏覽器 CORS 需實測 |
| CGU | 依 `https://air.cgu.edu.tw/workspace4/LLMAPI/api_call.html` 所對應的正式 API 契約實作 | 該網址看起來是操作頁而非明確 REST 規格；若無 CORS／模型 API，需提供手動設定或獨立受控 relay 的決策 |

統一 adapter 必須回傳：`providerId`、`modelId`、`displayName`、`capabilities`、`limits`（若可取得）、`source`、`lastCheckedAt`。Key 不得進入 log、匯出 JSON、錯誤訊息或 prompt。

## 5. 專有名詞、姓名與參考資料策略

### 5.1 來源優先級

1. 使用者明確確認的詞彙表／姓名表。
2. 會議來源中可讀且重複出現的原文。
3. PDF／文字參考資料中可定位的內容。
4. LLM 推測（只能標為候選，不得直接覆寫）。

### 5.2 處理流程

- PDF 以頁為單位抽取文字；TXT／MD 直接讀取；所有來源先轉成安全純文字。
- 以本地搜尋／分段方式找出與當前段落相關的參考片段；MVP 不要求雲端向量資料庫。
- 將詞彙表、參考片段與原始逐字稿一起送給所選模型，但設定檔只傳必要片段，避免整份文件外洩。
- 模型輸出結構化結果：`revisedText`、`changes[]`、`terms[]`、`uncertainties[]`、`evidence[]`。
- UI 以 diff 顯示每個改動；姓名／專有名詞若非使用者確認，顯示「待確認」並保留原文。

### 5.3 禁止事項

- 不因字音相近自動改名。
- 不把 PDF 中的猜測、舊資料或其他人名當成本次會議事實。
- 不刪除原文；不接受模型未符合 schema 的文字作為已核准成果。

## 6. 會議成果輸出規格

以單一中間資料模型渲染以下輸出，編號、人物、期限、狀態必須一致：

1. `01_會後通知信.md`：可直接複製的草稿，明確標示未寄出。
2. `02_完整會議紀錄.md`：議題、背景、方案、決策理由、未採用方案、影響／風險、來源依據。
3. `03_本次待辦事項.md`：每筆 `ACT-...` 的主責、協作人、完成標準、期限、狀態、關聯。
4. `04_下次會議議程.md`：依受阻／逾期／未決／驗收等優先級排列。
5. `05_會議成果彙整_A4列印.html`：整合前四份、附錄待確認事項、可離線列印。

缺漏資料使用 `待確認`、`未提供`、`未提及`，不可使用目前日期猜測會議日期。

## 7. 資料模型（概念）

```text
MeetingProject
├─ metadata: title, date?, timezone, location?, attendees[]
├─ audio: sourceType, fileName, duration, hash, localOnly
├─ transcript: segments[] { id, start, end, speaker?, originalText, editedText?, confidence? }
├─ references[] { id, fileName, type, size, pages?, extractedText, hash }
├─ glossary[] { canonical, aliases[], kind, locked, evidence[] }
├─ llmSelection { providerId, modelId, endpoint?, testedAt }
├─ generations[] { promptVersion, inputHash, output, status, createdAt }
└─ meetingOutputs { notice, minutes, actions, agenda, a4Html }
```

API Key 僅存在執行期 secret store，不放入 `MeetingProject`。匯出時只放 provider／model，不放 Key 或完整 prompt 中的機密內容。

## 8. 非功能需求

- 隱私：預設音訊、逐字稿、參考資料只在本機；外送前明確顯示 provider、模型與資料範圍。
- 安全：CSP、嚴格 HTML escape、依賴鎖定、無分析追蹤；Key 不進 URL、localStorage、Git、log。
- 效能：轉錄在 Worker 執行；長音訊顯示進度與可取消；UI 在推論期間仍可操作。
- 可用性：鍵盤可操作、表單有 label、狀態有文字而非只用顏色、支援繁體中文。
- 相容性：以最新 Chrome／Edge／Firefox／Safari 為目標；WebGPU 不可用時提供 WASM fallback 或明確提示。
- 可重現：每次生成保存 prompt 版本、模型 ID、輸入 hash 與時間，但不保存 Key。
- 部署：GitHub Pages 可用相對路徑、SPA fallback 策略與自動化 build；不依賴長駐後端。

## 9. 驗收條件（MVP）

- 能以本地音訊完成一次轉錄，期間頁面不凍結，並能編輯及下載逐字稿。
- 四家 provider 均能走完「輸入 → 測試 → 模型清單／明確錯誤 → 選模型」流程；CGU 若契約尚未可用，產品必須清楚標示阻塞原因，不得假成功。
- 加入一份含姓名與專有名詞的 PDF／文字檔後，生成結果能顯示引用依據與待確認詞，不直接覆寫原文。
- 生成的四份 Markdown 與 A4 HTML 的 `DEC-...`、`ACT-...`、負責人、期限、狀態完全一致。
- A4 HTML 無網路時仍可開啟，列印設定為 A4 直式，內容不因表格過寬而裁切。
- 對錯誤 Key、配額耗盡、模型不可用、CORS、PDF 解析失敗、模型輸出格式錯誤均有可理解的處理訊息。
